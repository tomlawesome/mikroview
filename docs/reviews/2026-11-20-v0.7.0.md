# Pre-release review: v0.7.0

Reviewed: everything that changed between the v0.6.1 audit baseline
(`7163478b`) and `bc5254cb`, in four audits, then a follow-up pass on the
range after that point (`918db95c..e3db7b12`, below). The next release
reviews what changes after `e3db7b12`, plus the security stage's result.

**Disclosure rule.** As for v0.6.1: security findings appear here only
once fixed and named with their fix commit; anything open lives in a
confidential issue. This file is never deleted.

## Scope

The release is large, and one audit covers at most 15,000 new lines, so
the review ran in four audits: two rounds on the first batch, one on the
second batch, and the older development range from the v0.6.1 baseline
on. About 77,000 new lines were counted across the code, tests,
documentation, delivery and tooling. Code that moved to the shared
authentication module is that module's own audit; this release's audit
covered how the product uses it. Tracking issue #1426.

## Method

Each audit ran the stages that fit what it read: a documentation pass
(facts, plain language, records), an engines pass (the full scenario
suite under all three browser engines), Function with its test pass,
Robustness and Safety, property passes that follow one property across
the whole range, a pass over moved and deleted code, and a gaps round
that read whatever an earlier pass had only searched. Security ran last
and alone, on the final fix head, under several lenses. Every High or
Medium finding went to an independent judge, and a sweep re-read every
Low to catch ones graded too low. Every fix carries a test written first
by a different agent from the fixer, and was reviewed by an agent that
did not write it. Design rulings: the owner.

## Results

| Audit | High | Medium | Low | Notes |
|---|---|---|---|---|
| First batch, first round | 2 | 3 | 2 | 13 |
| Second batch | 0 | 3 | 4 | 4 |
| First batch, second round | 0 | 3 | 14 | 2 |

Grades changed by ruling or sweep: 2, 2, 3 and 24 across the four
audits, in both directions. Findings refuted by ruling or by test: none
in the first three audits; none in the fourth. A number of findings were
duplicates of one another and are counted once.

Every High, and every Medium graded as needing a fix for this release,
was fixed before it. Mediums and Lows graded for a later release, and the
Notes, are tracked as batched follow-up work (#1478 (Notes), #1534
(Lows), #1547 (confidential batch)). The documentation pass findings
were fixed, except those that were false or needed no change.

Security stage: one Medium found and fixed before release; the other
security findings were Medium or Low, none graded as needing a fix for
this release, and are listed in the confidential issue above. They will
be named here once fixed.

## Fix review

Every fix was proved with a test and re-reviewed by a separate reviewer.
A small number of fixes were judged Broken on review and were redone,
each proved by a test from a different author; the rest were upheld,
some after Low follow-ups that were fixed. The full gate was green on the
final head.

## Follow-up pass (`918db95c..e3db7b12`)

After the audit point, a further pass read the range that had been
merged since: five chunks read. It found one Low, a failure line nested
inside a paragraph, which was fixed. One further finding was refuted by
ruling.

Security follow-up: every changed line of code in the range was read
under the security stage's lenses, with no findings.
