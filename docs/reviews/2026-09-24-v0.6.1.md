Reviewed: `8216621a` (`dev` after the M19 merge and its screenshot/CI
follow-ons; six-stage pass) and `eb703ce1` (the fix batch carrying every

## Method

Six stages in order -- Function, Efficiency, Professionalism,
Robustness, Quality, Safety -- run as sequential passes over the same
head (`911f08a2..8216621a`, 238 commits, 304 files, ~28,700 added
lines). Each stage is sliced six ways (`internal/api`;
`internal/{auth,config,prefs,settings}`; the rest of `internal/` and
root Go; `frontend/src/components`; the rest of `frontend/` including
scripts; ops -- CI, scripts, docs, deploy, tools) plus gap finders that
read whatever a slice's own finder left unread, and property passes that
read one property across the whole tree rather than one directory
(every store write; every second-factor flow; every account state
against every gate; every preference key against its docs). One finder
per slice per stage, judging that lens only. Every medium or high
finding goes to an independent refuter, given the finding and the code
but never the finder's reasoning, and briefed to refute on uncertainty.

Security runs once, alone, after every stage is fixed, on the head those
fixes reached (`eb703ce1`, range `911f08a2..eb703ce1`): five finders
sliced by area (API authn/authz; auth/config/prefs and root Go; the rest
of `internal/`; `frontend/src`; CI, containers, scripts and supply
chain) plus two property passes -- every route against its guards, every
attacker-reachable value against every sink -- and gap finders for the
scripts in full, SECURITY.md's own promises against the code, sinks no
test reaches, and per-user store growth.

Every fix carries a test that fails before it and passes after, and gets
its own fix review.

Finders and refuters: Claude Sonnet 5. Judging, severity and triage for
the six stages and their fix reviews: Claude Opus 5.5. Judging for the
security stage: Claude Fable 5. Design rulings: the owner, 2026-09-24.

was upheld with no redo.
