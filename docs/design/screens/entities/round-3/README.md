## Direction AA — the survey, upright

The territory turned on its axis: the terrain is a **vertical column
at the left**, the roll works **beside it** on the right, one shared
selection and one shared scroll spanning both.

- **What verticality buys**: the terrain can be as long as it likes —
  a /24 with two hundred speakers grows the page downward, the page's
  natural direction, instead of fighting a fixed-width strip; the
  roll's dead space goes to work (terrain and record shoulder to
  shoulder, row for row); and vertical is the house's own orientation
  — the fall drops, the register reads downward (#363), so the map
  stops being a landscape guest in a portrait app.
- **Y's laws carry verbatim**: honest geography only (the outside
  strip stays mapless, ordered by last visit; the unclaimed range is
  written down the ruler it describes, in vertical writing); the
  stake grammar (solid plaque named, dashed hollow unnamed, amber
  tick seen-this-hour); label lanes alternate reach for the crowded
  low octets; the roll is still the whole page — the terrain adds
  reading, never gates doing.
- **Rules read downward** as horizontal tally bars — the register's
  own grammar: loudest first top-to-bottom, width = the hour's tally,
  ink = the fall's verdict colours, counts printed, scale declared.
  Ports run down the banded ruler (well-known at the top, ephemeral
  at the foot). One axis for every terrain.
- **Naming, upright**: the field opens at the stake and in the row,
  now side by side — both mirrors on screen at once, which the
  stacked layout could not promise.
- **The pocket survey (mobile)**: the roll is the page, full-width;
  the terrain lives in a left-edge **drawer behind a pull tab** that
  names what it holds. The drawer holds no verb — choosing a stake
  closes it onto that thing's row; scrim, handle, Esc and a left-drag
  close it; 200 ms slide, instant under reduced motion. Because the
  vertical map is a narrow column by design, desktop and phone are
  the same drawing, docked or undocked. The mobile shell itself
  (where the rail goes on a phone) is #486's question, drawn
  minimally on purpose.
- Keyboard: arrows walk rows and the map's highlight follows; `m`
  moves focus to the map and arrows walk stakes; same single
  selection either way. Screen readers get each terrain as one
  described image and the roll as the operable list, unchanged.
- #490's read-only grammar carries unchanged (proven in rounds 1–2;
  a viewer's drawer simply has no naming field to open).
