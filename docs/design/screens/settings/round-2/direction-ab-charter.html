Settings pages are an artefact of databases, not of understanding. The question an operator actually has is "how is this network kept?", and its natural form is a document. The charter writes the whole configuration as articles — who may look in, which machines may speak, what is watched for, what is kept — with every editable value as a term in a sentence, and the audit log where a document keeps its history: the margin.
One document, one place. "Which page is that setting on?" dissolves — there is one page, it reads top to bottom in under a minute, and / finds any word of it. The rail's Admin section collapses to The charter (plus Entities and Fleet, which are records, not rules).
Facts and terms share sentences. "Last spoke at 14:02" (fact, plain ink) sits beside "revocable in a word" (term, underlined) — because configuration only means anything against what the system is actually doing. The charter is the only settings form that can say both in one breath.

The charter · article V — the edges

V · What the charter does not govern

The listener's doors — syslog, TLS, trusted proxies — are set in config.yaml and read at start; the charter states them but cannot amend them, and says so here rather than pretending. Run setup… is a workshop, not an article: it mints credentials, so it stays the admin's outright. Passwords and SSO links are each person's own door. Entities is the network's dictionary and keeps its own page (#489); the charter cites names, it does not keep them.

VI · The server's own clause

Whatever any page renders, the server refuses a non-admin's amendment — every write is 403 without the admin role. The charter's readability to viewers is itself a deliberate grant: one route, one authz-matrix row, opened on purpose. No key's value survives its minting sentence anywhere the API can repeat.

The charter about itself. The estate's edges and the API clause are articles too — written where every reader, admin or viewer, will actually meet them, instead of in a design document nobody operates from.
Honesty as an article. What is configured outside the UI says so; what only admins may touch says why; what the server enforces is written as the network's own law. The document form makes the system's rules legible in the same voice as its values — which is the whole premise.
What the build inherits. One charter view composed from the existing GETs (users, tokens, definitions, audit, status); terms map 1:1 onto existing write endpoints; the margin is the audit log filtered by article. No new stores. The risk to weigh: prose templates need care per locale and per fact-shape — the round README carries the cost note.
