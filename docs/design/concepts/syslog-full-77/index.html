Where does "⚠ syslog full" live now? — #77

The old stream toolbar carried a warning when MikroView turned away a configured router's syslog connections because its connection pool was full. That toolbar was retired when the scene bar was built (1c0f85d) and the warning lost its home — the only retired control that hides data loss rather than costing a convenience (tracked as item 1 on #691). The backend still reports it on every GET /api/stats call; only the display disappeared. This mockup proposes two places for it to come back: the same banner slot ConnectionBanner.svelte already uses, and a persistent line in Settings beside the buffer readout.

One story throughout: router branch-e4a1 · 43 connection attempts turned away · 24 of 24 syslog slots in use.

Bottom banner (feed drop): events MikroView already has, just not delivered to this tab — wsDropped resets to zero the moment this connection re-opens. They can legitimately fire together, as here: the same load spike that saturated the syslog pool is also outrunning the websocket.
